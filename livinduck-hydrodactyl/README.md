# Hydrodactyl 6.4.1

Hydrodactyl is the maintained successor to Pyrodactyl. This package uses the
upstream release image with MariaDB 11.4 and Redis 7.4, pinned to public
multi-architecture digests. Both AMD64 and ARM64 are supported.

## First launch

Install **Hydrodactyl** from the LivinDuck store, open it, and complete the
administrator account wizard. Database migrations and game templates are
initialized automatically. No terminal commands, database credentials, shared
default passwords, domain purchase or SMTP account are needed for panel setup.
The first launch may take a few minutes. Subsequent launches open the dashboard
or login page; the wizard closes once an account exists.

Umbrel login protects the browser and setup wizard. Hydrodactyl also has its
own account login. The browser launch port is **39404**.

## Game servers and email

This is the **panel**, not an all-in-one game hosting appliance. Install Wings
or Elytra on a separate machine and add it through Administration → Nodes.
Use the node configuration generated by the panel. The node must reach the
panel, and both the panel and your browser must reach the node's API address.
Use a hostname/IP reachable from those machines; `.local` discovery may not
work across networks. For remote access use appropriate DNS and HTTPS for both
panel and node. No node, game ports, Docker socket or game engine is provisioned
on Umbrel by this package.

Only `/api/remote/*` bypasses Umbrel login so nodes can call the panel with their
own bearer credentials. All other routes retain Umbrel authentication.
External application/client API consumers still need an Umbrel session.

Email is optional. Configure SMTP through Administration → Settings → Mail
before relying on invitations, notifications or password-reset emails.
Until then, email delivery fails while the panel remains usable. Keep your
administrator password in a password manager.

## Persistence and recovery

Accounts, nodes, settings and encrypted credentials live in `data/database`.
`data/var/.env` holds the application encryption key and hash salt and must be
backed up with the database. Losing the key can make encrypted settings and 2FA
data unreadable. Redis sessions/queues persist in `data/cache`; uploaded panel
assets persist in `data/uploads`; logs persist in `data/logs`.

Database and Redis credentials derive independently from Umbrel's device seed.
Full recovery needs the original Umbrel seed as well as the app data. Stop the
app for a consistent filesystem backup. Back up game worlds and server backups
on the separate node independently. Restore the complete pre-update backup if
a future database migration must be rolled back; downgrading the image alone
does not undo migrations.

## Validation and attribution

`tests/smoke_hydrodactyl.py` exercises the packaged containers on disposable
AMD64 and ARM64 GitHub runners: browser onboarding, admin access, rejected
unauthorized requests, closed setup routes, restart/recreation persistence,
encrypted settings and uploaded files. The store also runs Umbrel's pinned
package linter and checks anonymous image access.

These are standalone container tests. An actual Umbrel installation, Umbrel's
live authentication proxy and a real game node are not tested by this workflow.
Publishing this package does not install it on the NAS.
